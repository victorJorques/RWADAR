## Claves que da Víctor

Tres claves, una por servicio y cada una con lo mínimo. Víctor las crea y las
pega él: nunca en un chat, un archivo ni una captura. Las tres se pegan igual:
**GitHub › el repositorio › Settings › Secrets and variables › Actions › New
repository secret**, con el nombre exacto de la primera columna en «Name» y la
clave en «Secret». Los flujos nunca las enseñan, y cada una llega solo a los
pasos que la usan.

| Secreto | Dónde se crea | Permisos (solo estos) | Lo usan |
|---|---|---|---|
| `CLOUDFLARE_DNS_TOKEN` | dash.cloudflare.com › el icono de la cuenta, arriba a la derecha › My Profile › API Tokens › Create Token › plantilla «Edit zone DNS» | Permissions: **Zone · DNS · Edit** y, con «+ Add more», **Zone · Zone · Read**. Zone Resources: **Include · Specific zone · `rwadar.app`**. Sin filtro de IP (GitHub cambia de IP). Puede llevar fecha de caducidad: al caducar, se crea otra y se pega encima | «Dominio de correo»: `estado` y `preparar-dominio` |
| `LETTERMINT_TEAM_TOKEN` | Lettermint › Manage team › API Tokens › Create token. Es un token **de equipo**, no de proyecto | `read:team`, `read:projects`, `write:projects`, `read:domains`, `write:domains`, `read:routes`, `write:routes` y `read:suppressions`. En Lettermint escribir no da permiso para leer: se marcan los dos. Ni `*` ni nada de miembros, roles, mensajes o webhooks | Todo «Dominio de correo», `smtp-lettermint` y `sincronizar-bajas` («Correo Lettermint», que ya usaba este nombre) |
| `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens › Generate new token, **con alcance**: solo el proyecto RWAdar (`exgpmjpaaebyoolpwced`) | **Auth Config: Read-write** · **Project Settings: Read-write** (Supabase lo pide para cambiar Auth) · **Database: Read** (solo para saber si se puede actualizar Postgres; sin él, `estado` lo dice y sigue). La caducidad más corta que vaya bien (hasta un año) | «Supabase (gestión de Auth)» |

- `crear-token-base` usa además `SUPABASE_DB_URL`, que ya existe (el de la
  copia de seguridad): no hay que crear nada.
- De dónde salen los permisos (consultado el 08/11/2026): Lettermint,
  https://lettermint.co/docs/platform/teams/api-tokens (la lista de
  «abilities»; no dice cuál pide cada llamada: **verificar** con el primer
  `estado`, que si le falta alguno da un 403 y lo dice); Supabase,
  https://supabase.com/docs/guides/platform/personal-access-tokens (los
  tokens con alcance empiezan por `sbp_fc`); Cloudflare, la plantilla «Edit
  zone DNS» más la lectura de la zona.
- Si una clave se filtra: se revoca en el mismo panel, se crea otra con los
  mismos permisos y se pega encima del secreto (mismo nombre). El token de
  Lettermint es el más delicado: con `write:projects` podría borrar
  proyectos y tokens. Por eso no lleva nada más.

1. **→ flujo.** Las plantillas `confirmar-alta.html` y `recuperar-acceso.html`

   había, como artefacto del flujo, por si hay que volver atrás. `estado`
   dice, por SHA-256, si las de Supabase son iguales a las del repositorio.
2. **→ flujo.** El SMTP de Supabase Auth a Lettermint (punto 5.8.4): acción
   `smtp-lettermint`, con `cuenta_verificada` = `SI` y el remitente
   `avisos@rwadar.app`. Antes de crear nada comprueba que la API de
   Lettermint también da la cuenta por verificada, que el dominio está
   verificado, que las plantillas ya son las del repositorio y que la
   privacidad publicada ya nombra a Lettermint. Crea el token «RWAdar Auth
   (SMTP)» (nadie lo ve), enseña el SMTP de antes (para volver atrás) y pone
   host `smtp.lettermint.co`, puerto `587`, usuario `lettermint`, el token
   como contraseña, el remitente y el nombre «RWAdar». Esos tres datos salen
   de la guía de Lettermint
   (https://lettermint.co/docs/guides/send-email-with-smtp, 08/11/2026) y el
   flujo los compara con lo que diga su API al crear el token.
3. **Víctor mira el buzón.** Con `correo_prueba` = su dirección, el mismo
   flujo pide a Supabase un correo real de recuperación y cuenta solo el
   código HTTP. Víctor abre el original y lo enseña (punto 5.8.5): sin
   píxel, el enlace sin reescribir y la dirección postal en el pie.
4. **Víctor.** Si todo va bien, borrar la contraseña de aplicación del Gmail
